# Bugfix Requirements Document

## Introduction

В Dashboard.tsx обнаружены два взаимосвязанных бага, связанных с состоянием UI-компонентов:

1. **Очистка уведомлений не работает** — при нажатии «Очистить все» уведомления кратковременно исчезают, а затем появляются снова из-за race condition между `clearAllNotifications` и `fetchNotifications`, вызываемой из `markNotificationsRead`.

2. **Модальное окно достижений появляется повторно** — после закрытия модального окна достижения (крестик или «Не сейчас»), оно появляется снова при следующем обновлении данных, потому что milestone не помечается как «просмотренный» в базе данных.

Оба бага ухудшают пользовательский опыт и вводят пользователей в заблуждение.

## Bug Analysis

### Current Behavior (Defect)

1.1 WHEN пользователь нажимает на иконку колокольчика, THEN система вызывает `markNotificationsRead()` независимо от того, открывается или закрывается панель уведомлений

1.2 WHEN `markNotificationsRead()` вызывается, THEN система вызывает `fetchNotifications()` в конце выполнения, что перезаписывает локальное состояние уведомлений данными из БД

1.3 WHEN пользователь нажимает «Очистить все» после открытия панели, THEN уведомления кратковременно исчезают (state=[]), но затем появляются снова, так как pending `fetchNotifications` из `markNotificationsRead` разрешается позже и перезаписывает пустой массив

1.4 WHEN пользователь закрывает модальное окно достижений (крестик или «Не сейчас»), THEN система не сохраняет факт просмотра milestone в базе данных

1.5 WHEN `earnedTotal` меняется (при каждом вызове `fetchMyTasks`), THEN useEffect в AchievementModal срабатывает заново и показывает модальное окно повторно, так как milestone не был отмечен как «seen»

1.6 WHEN `onClose` вызывается в Dashboard, THEN выполняется пустая функция `() => { }`, которая не обновляет состояние родительского компонента

### Expected Behavior (Correct)

2.1 WHEN пользователь нажимает на иконку колокольчика для ОТКРЫТИЯ панели, THEN система SHALL пометить непрочитанные уведомления как прочитанные, обновив только локальное состояние (set is_read=true) без повторного запроса fetchNotifications

2.2 WHEN пользователь нажимает на иконку колокольчика для ЗАКРЫТИЯ панели, THEN система SHALL только закрыть панель без вызова markNotificationsRead

2.3 WHEN пользователь нажимает «Очистить все», THEN система SHALL удалить уведомления из БД и установить state=[] без последующей перезаписи состояния

2.4 WHEN пользователь закрывает модальное окно достижений (крестик или «Не сейчас»), THEN система SHALL сохранить milestone как «seen» в БД (поле `seen_milestones` в achievements JSON)

2.5 WHEN пользователь закрывает модальное окно достижений, THEN система SHALL обновить состояние родительского компонента, чтобы модальное окно не рендерилось повторно

2.6 WHEN useEffect в AchievementModal проверяет milestones, THEN система SHALL проверять как `shared_milestones`, так и `seen_milestones` и не показывать уже просмотренные достижения

### Unchanged Behavior (Regression Prevention)

3.1 WHEN пользователь получает новое уведомление, THEN система SHALL CONTINUE TO показывать индикатор непрочитанных (красную точку) на иконке колокольчика

3.2 WHEN пользователь открывает панель уведомлений, THEN система SHALL CONTINUE TO отображать все текущие уведомления в обратном хронологическом порядке

3.3 WHEN пользователь делится достижением через VK или Telegram, THEN система SHALL CONTINUE TO начислять бонус +50₽ и сохранять milestone в `shared_milestones`

3.4 WHEN пользователь достигает нового milestone (100₽, 1000₽, 5000₽) впервые, THEN система SHALL CONTINUE TO показывать модальное окно достижений с конфетти

3.5 WHEN пользователь нажимает «Очистить все» при отсутствии pending-запросов, THEN система SHALL CONTINUE TO полностью очищать список уведомлений и показывать toast «Уведомления очищены»

3.6 WHEN уведомление помечается как прочитанное, THEN система SHALL CONTINUE TO корректно обновлять счётчик unreadCount до 0
